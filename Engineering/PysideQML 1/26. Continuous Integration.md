
**Part 29: Continuous Integration (CI/CD)**. This part is about **automating your workflow** — testing, building, and distributing your PySide6 + QML apps without manual effort. With CI/CD, every time you push code to GitHub or GitLab, your app can automatically run tests, build executables, and even publish releases.

# Part 29: Continuous Integration (CI/CD)

## 📂 Why CI/CD Matters

- **Consistency** → Builds are reproducible and reliable.
    
- **Automation** → No manual packaging every time.
    
- **Quality** → Tests run automatically, catching bugs early.
    
- **Distribution** → Artifacts (executables, installers) are generated and uploaded for users.
    

## 📝 Step 1: GitHub Actions Workflow

Create a file `.github/workflows/build.yml`:

yaml

```
name: Build and Test

on:
  push:
    branches: [ "main" ]
  pull_request:
    branches: [ "main" ]

jobs:
  build:
    runs-on: ubuntu-latest

    steps:
    - name: Checkout code
      uses: actions/checkout@v3

    - name: Set up Python
      uses: actions/setup-python@v4
      with:
        python-version: "3.10"

    - name: Install dependencies
      run: |
        python -m pip install --upgrade pip
        pip install -r requirements.txt
        pip install pytest pyinstaller

    - name: Run tests
      run: pytest backend/

    - name: Build executable
      run: pyinstaller --onefile --windowed main.py --icon=resources/app_icon.png

    - name: Upload artifact
      uses: actions/upload-artifact@v3
      with:
        name: myapp-executable
        path: dist/main
```

📌 This workflow:

1. Checks out your code.
    
2. Sets up Python.
    
3. Installs dependencies.
    
4. Runs tests.
    
5. Builds the executable.
    
6. Uploads the build artifact.
    

## 📝 Step 2: GitLab CI/CD Example

In `.gitlab-ci.yml`:

yaml

```
stages:
  - test
  - build

test:
  stage: test
  image: python:3.10
  script:
    - pip install -r requirements.txt
    - pip install pytest
    - pytest backend/

build:
  stage: build
  image: python:3.10
  script:
    - pip install pyinstaller
    - pyinstaller --onefile --windowed main.py
  artifacts:
    paths:
      - dist/
```

📌 Similar to GitHub Actions, but runs inside GitLab pipelines.

## 📝 Step 3: Release Automation

You can automatically publish builds to **GitHub Releases**:

yaml

```
- name: Create Release
  uses: softprops/action-gh-release@v1
  with:
    tag_name: v1.0.0
    name: "MyApp v1.0.0"
    files: dist/main
```

📌 This uploads your executable to a tagged release.

## 🧠 Key Concepts Learned

- **CI/CD pipelines** automate testing, building, and distribution.
    
- **GitHub Actions** and **GitLab CI/CD** are popular free solutions.
    
- **Artifacts** → built executables uploaded for download.
    
- **Release automation** → publish builds directly to users.
    

## ⚡ Extra Ideas

- Add **multi‑platform builds** (Windows, Linux, macOS runners).
    
- Integrate **code coverage** tools to measure test quality.
    
- Add **linting** (flake8, black) for clean code.
    
- Combine with **Part 28 (Distribution)** to ship installers automatically.
