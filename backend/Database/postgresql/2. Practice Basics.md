
## The Complete PostgreSQL Mastery Curriculum

Try to write each query in your terminal. Reveal the solution only after you have given it a solid try!

### Phase 1: The Basics (Filtering & Pattern Matching)

We will start with the fundamental building blocks of querying: choosing columns, filtering rows, handling strings, and using wildcards.

#### Challenge 1: Simple Selection & Aliasing

- **Concept:** `SELECT`, `AS` (renaming columns), `ORDER BY`.
    
- **Goal:** Retrieve all employee names and their salaries. Rename the columns to `Employee_Name` and `Yearly_Salary`, and sort them from highest to lowest salary.
    



```SQL
SELECT name AS "Employee_Name", salary AS "Yearly_Salary"
FROM employees
ORDER BY salary DESC;
```

#### Challenge 2: Basic Filtering & Comparison Operators

- **Concept:** `WHERE` clause, `>`, `<`.
    
- **Goal:** Find all transactions where the amount is strictly greater than 50.00.
    

SQL

```SQL
SELECT transaction_id, user_id, amount, transaction_date
FROM transactions
WHERE amount > 50.00;
```

#### Challenge 3: Wildcards & Pattern Matching (String Functions)

- **Concept:** `LIKE`, `ILIKE` (case-insensitive), `%` (any characters), `_` (exactly one character).
    
- **Goal:** Find all users whose emails end with `example.com` and have exactly **5 characters** in the username prefix before the `@` symbol (Hint: `alice` and `david` have 5 letters).
    

SQL

```SQL
-- The underscore '_' represents exactly one character. 
-- Five underscores followed by '@example.com' targets exactly 5-letter usernames.
SELECT user_id, email
FROM users
WHERE email ILIKE '_____@example.com';
```

#### Challenge 4: Logical Operators & Range Filtering

- **Concept:** `AND`, `OR`, `BETWEEN`.
    
- **Goal:** Find all transactions that occurred in the month of **March 2025** with an amount between 10.00 and 200.00.
    

SQL

```SQL
SELECT transaction_id, amount, transaction_date
FROM transactions
WHERE transaction_date BETWEEN '2025-03-01 00:00:00+00' AND '2025-03-31 23:59:59+00'
  AND amount BETWEEN 10.00 AND 200.00;
```

#### Challenge 5: Handling Missing Data

- **Concept:** `IS NULL`, `IS NOT NULL`, `COALESCE`.
    
- **Goal:** List all subscriptions that are still active (meaning they have no `end_date`). If the `end_date` is null, display the text `'No End Date Specified'` using the `COALESCE` function.
    

SQL

```SQL
-- COALESCE returns its first non-null argument. 
-- Because end_date is a DATE type, we must cast the replacement text or convert the date to text.
SELECT subscription_id, user_id, status, start_date,
       COALESCE(end_date::TEXT, 'No End Date Specified') AS current_end_date
FROM subscriptions
WHERE end_date IS NULL;
```

### Phase 2: Intermediate (Aggregations, Joins & Groups)

Now that you can filter individual rows, let's learn how to group data, combine tables, and clean up results.

#### Challenge 6: Aggregating Data

- **Concept:** `COUNT()`, `SUM()`, `AVG()`, `ROUND()`.
    
- **Goal:** Find the total money processed, the average transaction amount (rounded to 2 decimal places), and the total number of transactions in our database.
    

SQL

```SQL
SELECT 
    COUNT(transaction_id) AS total_transactions,
    SUM(amount) AS total_revenue,
    ROUND(AVG(amount), 2) AS average_transaction_value
FROM transactions;
```

#### Challenge 7: Grouping Data

- **Concept:** `GROUP BY`.
    
- **Goal:** Calculate the total amount spent on transactions by _each_ user. Sort the output so the highest-paying user is at the top.
    

SQL

```SQL
SELECT user_id, SUM(amount) AS total_spent
FROM transactions
GROUP BY user_id
ORDER BY total_spent DESC;
```

#### Challenge 8: Filtering Grouped Data

- **Concept:** `HAVING` vs `WHERE`.
    
- **Goal:** Retrieve the user IDs of only those users who have made **more than 2 transactions**.
    

SQL

```SQL
-- WHERE filters individual rows *before* grouping. 
-- HAVING filters the calculated groups *after* grouping.
SELECT user_id, COUNT(transaction_id) AS transaction_count
FROM transactions
GROUP BY user_id
HAVING COUNT(transaction_id) > 2;
```

#### Challenge 9: Basic Table Joins

- **Concept:** `INNER JOIN`.
    
- **Goal:** Combine the `users` and `subscriptions` tables to display each user's email, their subscription status, and the start date of their subscription.
    

SQL

```SQL
SELECT u.email, s.status, s.start_date
FROM users u
INNER JOIN subscriptions s ON u.user_id = s.user_id;
```

#### Challenge 10: Multi-Table Joins & Cleanups

- **Concept:** Joining 3 tables, handling missing matches with `LEFT JOIN`.
    
- **Goal:** Show a list of all registered user emails, the name of the subscription plan they are on, and the monthly price of that plan. If a user does not have a subscription row at all, show `'No Subscription'` and `0.00` respectively.
    

SQL

```SQL
SELECT u.email, 
       COALESCE(p.plan_name, 'No Subscription') AS plan_name,
       COALESCE(p.price_monthly, 0.00) AS price_monthly
FROM users u
LEFT JOIN subscriptions s ON u.user_id = s.user_id
LEFT JOIN plans p ON s.plan_id = p.plan_id;
```

### Phase 3: Intermediate-Advanced (Date Math, String Parsing & Enums)

PostgreSQL has incredibly powerful engines built specifically for handling times, calendars, and semi-structured text.

#### Challenge 11: Date Math & Intervals

- **Concept:** `INTERVAL`, `AGE()`, Date subtraction.
    
- **Goal:** Find all subscriptions that ended or will end exactly **90 days** after they started.
    

SQL

```SQL
SELECT subscription_id, user_id, start_date, end_date,
       (end_date - start_date) AS active_days
FROM subscriptions
WHERE end_date - start_date = 90;
```

#### Challenge 12: Conditional Logic in Projections

- **Concept:** `CASE WHEN ... THEN ... ELSE END`.
    
- **Goal:** Classify employees into three categories based on their salary:
    
    - `High Earner` if salary is 150,000 or more
        
    - `Mid Earner` if salary is between 100,000 and 149,999
        
    - `Standard Earner` for anything else.
        

SQL

```SQL
SELECT name, salary,
       CASE 
           WHEN salary >= 150000.00 THEN 'High Earner'
           WHEN salary BETWEEN 100000.00 AND 149999.99 THEN 'Mid Earner'
           ELSE 'Standard Earner'
       END AS salary_class
FROM employees;
```

#### Challenge 13: Manipulating JSONB (The NoSQL in PostgreSQL Power)

- **Concept:** `->`, `->>`, JSONB matching.
    
- **Goal:** Extract the user's email and their preferred `device` from the nested `metadata` column for users who live in Canada (`CA`) or Germany (`DE`).
    

SQL

```SQL
SELECT email, 
       metadata->>'device' AS device_type,
       metadata->>'country' AS country
FROM users
WHERE metadata->>'country' IN ('CA', 'DE');
```

#### Challenge 14: Set Operators

- **Concept:** `UNION`, `UNION ALL`, `INTERSECT`.
    
- **Goal:** Write a single query that returns a list of all unique email domains used by users (hint: string splitting) _combined with_ a list of all distinct department names in the employee table.
    

SQL

```SQL
-- SUBSTRING combined with POSITION parses out the domain of the email string
SELECT DISTINCT SUBSTRING(email FROM POSITION('@' IN email) + 1) AS custom_name
FROM users

UNION -- UNION removes duplicates; UNION ALL would keep them.

SELECT DISTINCT department AS custom_name
FROM employees;
```

### Phase 4: Advanced (Subqueries, CTEs & Window Functions)

Now we enter the territory of elite database query writing. These concepts let you design algorithms inside SQL.

#### Challenge 15: Subqueries (Uncorrelated & Correlated)

- **Concept:** `IN`, `EXISTS`, Correlated subqueries.
    
- **Goal:** Find all users who have spent more than the _overall average_ transaction amount in a single transaction.
    

SQL

```SQL
-- Uncorrelated subquery (the subquery runs once, independently)
SELECT DISTINCT user_id
FROM transactions
WHERE amount > (SELECT AVG(amount) FROM transactions);
```

#### Challenge 16: Common Table Expressions (CTEs)

- **Concept:** `WITH` clauses.
    
- **Goal:** Using a CTE, calculate the total spending per user first, then select only the users whose total spending is larger than 100.00, along with their registration email.
    

SQL

```SQL
WITH user_spending AS (
    SELECT user_id, SUM(amount) AS total_spent
    FROM transactions
    GROUP BY user_id
)
SELECT u.email, us.total_spent
FROM user_spending us
JOIN users u ON us.user_id = u.user_id
WHERE us.total_spent > 100.00;
```

#### Challenge 17: Window Functions (Ranking)

- **Concept:** `ROW_NUMBER()`, `RANK()`, `PARTITION BY`.
    
- **Goal:** Rank employees within their respective departments by salary, with the highest-paid employee ranked `#1`.
    

SQL

```SQL
SELECT department, name, salary,
       RANK() OVER (PARTITION BY department ORDER BY salary DESC) AS salary_rank
FROM employees;
```

#### Challenge 18: Window Functions (Lead & Lag offsets)

- **Concept:** `LAG()`, `LEAD()`.
    
- **Goal:** For user `1`, display each of their transactions side-by-side with the amount of their _previous_ transaction to track change trends over time.
    

SQL

```SQL
SELECT transaction_id, transaction_date, amount,
       LAG(amount, 1) OVER (ORDER BY transaction_date) AS previous_transaction_amount
FROM transactions
WHERE user_id = 1;
```

### Phase 5: Mastery (Recursive Logic & Complex Aggregations)

These final challenges mimic the daily work of a Principal Database Engineer or Senior Data Analyst.

#### Challenge 19: Recursive CTEs (Walking Hierarchies)

- **Concept:** `WITH RECURSIVE`.
    
- **Goal:** Find every employee who reports (directly or indirectly) to **Michael (VP Engineering, Employee ID: 2)**. Display their name and their depth level in the organizational chart.
    

SQL

```SQL
WITH RECURSIVE engineering_hierarchy AS (
    -- Anchor member: Start directly with Michael's immediate reports
    SELECT employee_id, name, manager_id, 1 AS depth
    FROM employees
    WHERE manager_id = 2
    
    UNION ALL
    
    -- Recursive member: Join back to find reports of reports
    SELECT e.employee_id, e.name, e.manager_id, eh.depth + 1
    FROM employees e
    JOIN engineering_hierarchy eh ON e.manager_id = eh.employee_id
)
SELECT employee_id, name, depth 
FROM engineering_hierarchy;
```

#### Challenge 20: Pivot/Crosstab Reporting with Filter Aggregation

- **Concept:** `FILTER (WHERE ...)`.
    
- **Goal:** Write a single dashboard query that calculates the total amount of transactions categorized into three columns depending on whether they happened in: January, February, or March.
    

SQL

```SQL
SELECT 
    SUM(amount) FILTER (WHERE EXTRACT(MONTH FROM transaction_date) = 1) AS jan_revenue,
    SUM(amount) FILTER (WHERE EXTRACT(MONTH FROM transaction_date) = 2) AS feb_revenue,
    SUM(amount) FILTER (WHERE EXTRACT(MONTH FROM transaction_date) = 3) AS mar_revenue
FROM transactions;
```
