
## 1. The Core Filtering Drill (`WHERE` and Operators)

These challenges focus on pulling out precise rows using conditional logic, range boundaries, and pattern matching.

### Challenge 1: The Multi-Condition Filter (`AND`, `OR`)

- **Goal:** Find all users who live in the `US` **or** `UK` AND registered as a user after **February 1st, 2025**.
    


```SQL
SELECT user_id, email, created_at, metadata->>'country' AS country
FROM users
WHERE (metadata->>'country' = 'US' OR metadata->>'country' = 'UK')
  AND created_at > '2025-02-01 00:00:00+00';
```

> **Key Takeaway:** Always use parentheses `()` to group `OR` conditions. If you don't, the `AND` operator will take precedence and ruin your filter logic!

### Challenge 2: Negation & Lists (`IN`, `NOT IN`)

- **Goal:** Find all transactions that were **not** made by users `1`, `3`, or `5`.
    


```SQL
SELECT transaction_id, user_id, amount, transaction_date
FROM transactions
WHERE user_id NOT IN (1, 3, 5);
```

### Challenge 3: Case-Insensitive Substring Match (`ILIKE`, `%`)

- **Goal:** Find any employee whose department name contains the word "sales", regardless of whether it is written in uppercase, lowercase, or mixed case (e.g., `Sales`, `sales`, `SALES`).
    

SQL

```SQL
SELECT employee_id, name, department
FROM employees
WHERE department ILIKE '%sales%';
```

> **Key Takeaway:** `LIKE` is case-sensitive in PostgreSQL. `ILIKE` is a PostgreSQL-specific operator that ignores case, making it incredibly useful for searching user-entered text.

### Challenge 4: Single-Character Matches (`_`)

- **Goal:** Find all users whose device in `metadata` matches the exact template `i_hone` where `_` is a wildcard representing any single character (such as `iPhone`).
    

SQL

```SQL
SELECT user_id, email, metadata->>'device' AS device
FROM users
WHERE metadata->>'device' LIKE 'i_hone';
```

## 2. Mastering Relationships (`JOINS`)

Joining tables is the heart of relational databases. These questions cover matching records, keeping non-matching records, and combining datasets.

### Challenge 5: Classic `INNER JOIN` (Explicit Matching)

- **Goal:** List the email of every user who has an active subscription, along with the start date of their subscription.
    

SQL

```SQL
SELECT u.email, s.start_date, s.status
FROM users u
INNER JOIN subscriptions s ON u.user_id = s.user_id
WHERE s.status = 'active';
```

### Challenge 6: The `LEFT JOIN` (Dealing with Nulls)

- **Goal:** List **every single user** by email and show their subscription status. If they have never subscribed to anything and do not exist in the `subscriptions` table, show their status as `No Subscription Data`.
    

SQL

```SQL
-- We use COALESCE to handle the null value returned for unmatched users
SELECT u.email, 
       COALESCE(s.status::text, 'No Subscription Data') AS status
FROM users u
LEFT JOIN subscriptions s ON u.user_id = s.user_id;
```

### Challenge 7: Multi-Table Joins (The Chain)

- **Goal:** Display a list showing the user's `email`, the plan `price_monthly`, and the plan `plan_name` for all users with an active subscription.
    

SQL

```SQL
SELECT u.email, p.plan_name, p.price_monthly
FROM users u
INNER JOIN subscriptions s ON u.user_id = s.user_id
INNER JOIN plans p ON s.plan_id = p.plan_id
WHERE s.status = 'active';
```

> **Key Takeaway:** You can chain as many `JOIN` statements as you need. PostgreSQL will build a plan to join them from left to right or based on index optimizations.

### Challenge 8: Self-Joins (Self-Reference mapping)

- **Goal:** Show a list of all employees and the name of their direct manager. If they don't have a manager (like the CEO), display `'No Manager'`.
    

SQL

```SQL
-- We join the employees table to itself by giving it two different aliases: 'emp' and 'mgr'
SELECT emp.name AS employee_name, 
       COALESCE(mgr.name, 'No Manager') AS manager_name
FROM employees emp
LEFT JOIN employees mgr ON emp.manager_id = mgr.employee_id;
```

## 3. Summarizing Data (`GROUP BY` & Aggregations)

In production, you are constantly asked to calculate metrics like daily sales, average usage, or item counts.

### Challenge 9: Simple Counts & Sums

- **Goal:** Calculate the total number of transactions and the total sum of money processed in our platform.
    

SQL

```SQL
SELECT COUNT(*) AS total_transaction_count, 
       SUM(amount) AS total_revenue
FROM transactions;
```

### Challenge 10: Segmented Aggregations (`GROUP BY`)

- **Goal:** For each department in the `employees` table, find the average salary and the total number of employees working there.
    

SQL

```SQL
SELECT department, 
       COUNT(*) AS employee_count, 
       ROUND(AVG(salary), 2) AS average_salary
FROM employees
GROUP BY department;
```

### Challenge 11: Filtering Segments (`HAVING`)

- **Goal:** Find all departments where the average salary is greater than **120,000.00**.
    

SQL

```SQL
SELECT department, 
       ROUND(AVG(salary), 2) AS average_salary
FROM employees
GROUP BY department
HAVING AVG(salary) > 120000.00;
```

> **Key Takeaway:** Remember that `WHERE` filters individual rows _before_ they are grouped together. `HAVING` filters the computed average _after_ the grouping has taken place.

### Challenge 12: Unique Counts (`COUNT DISTINCT`)

- **Goal:** Calculate how many **unique** users made a transaction in our system. (If Alice made 4 transactions, she should only count as 1 unique active user).
    

SQL

```SQL
SELECT COUNT(DISTINCT user_id) AS unique_paying_customers
FROM transactions;
```

## 4. Cleaning Up Outputs (Functions & Formatting)

Data in raw tables is often ugly or formatted poorly. These functions help format dates, change data types, and apply conditional logic.

### Challenge 13: Cleaning String text (`LOWER`, `UPPER`, `CONCAT`)

- **Goal:** Output a column named `greeting` that reads: `"HELLO, [EMPLOYEE NAME IN ALL CAPS] FROM THE [DEPARTMENT IN ALL CAPS] DEPARTMENT!"` for every employee.
    

SQL

```SQL
SELECT CONCAT('HELLO, ', UPPER(name), ' FROM THE ', UPPER(department), ' DEPARTMENT!') AS greeting
FROM employees;
```

### Challenge 14: Extracting Date Parts (`EXTRACT`)

- **Goal:** From the `transactions` table, extract the month number and day of the month from the transaction date.
    

SQL

```SQL
SELECT transaction_id, 
       EXTRACT(MONTH FROM transaction_date) AS txn_month,
       EXTRACT(DAY FROM transaction_date) AS txn_day
FROM transactions;
```

### Challenge 15: Safe Division & Type Casting (`CAST`, `::`)

- **Goal:** Calculate the percentage of Ryan's salary relative to Sarah's (the CEO) salary. Round the percentage to 1 decimal place.
    

SQL

```SQL
SELECT 
    (SELECT salary FROM employees WHERE name LIKE 'Ryan%') AS ryan_salary,
    (SELECT salary FROM employees WHERE name LIKE 'Sarah%') AS ceo_salary,
    ROUND(
        ((SELECT salary FROM employees WHERE name LIKE 'Ryan%') / 
         (SELECT salary FROM employees WHERE name LIKE 'Sarah%')) * 100, 
        1
    ) AS salary_percentage;
```

### Challenge 16: Conditional Formatting (`CASE WHEN`)

- **Goal:** Write a query that reads the `price_monthly` from plans and displays a label:
    
    - If price is 0: `'Free'`
        
    - If price is less than 50: `'Affordable'`
        
    - If price is 50 or more: `'Premium'`
        

SQL

```SQL
SELECT plan_name, price_monthly,
       CASE 
           WHEN price_monthly = 0.00 THEN 'Free'
           WHEN price_monthly < 50.00 THEN 'Affordable'
           ELSE 'Premium'
       END AS pricing_tier
FROM plans;
```

## 5. Subqueries & Result Sets

Using the output of one query inside another query is a foundational skill for dealing with dynamic data.

### Challenge 17: Basic Subquery (`IN`)

- **Goal:** Select all user emails from the `users` table who have an active subscription record in the `subscriptions` table.
    

SQL

```SQL
SELECT email 
FROM users
WHERE user_id IN (
    SELECT user_id 
    FROM subscriptions 
    WHERE status = 'active'
);
```

### Challenge 18: Aggregate Subquery Comparison

- **Goal:** List the names and salaries of all employees who make **more** than the average company salary.
    

SQL

```SQL
SELECT name, salary
FROM employees
WHERE salary > (SELECT AVG(salary) FROM employees);
```

### Challenge 19: The `EXISTS` Operator

- **Goal:** Use the `EXISTS` operator to find all users who have made **at least one** transaction.
    

SQL

```SQL
SELECT u.user_id, u.email
FROM users u
WHERE EXISTS (
    SELECT 1 
    FROM transactions t 
    WHERE t.user_id = u.user_id
);
```

> **Key Takeaway:** `EXISTS` is incredibly efficient. Instead of gathering all matching rows like `IN` does, `EXISTS` stops scanning the moment it finds the very first match.

### Challenge 20: Sorting by Multi-Column priority (`ORDER BY`)

- **Goal:** Get a clean list of all transactions sorted first by `user_id` (ascending), and then by `amount` (descending) so you can easily see the biggest purchases for each user.
    

SQL

```SQL
SELECT user_id, amount, transaction_date
FROM transactions
ORDER BY user_id ASC, amount DESC;
```
