
## 1. The Schema Design

Here is how our tables relate to one another. We have users, subscription plans, historical transactions, and a self-referencing employee hierarchy to practice complex organizational tree structures.

## 2. Database Setup & Data Ingestion

Copy and paste this script directly into your PostgreSQL terminal or tool (like pgAdmin or DBeaver). It will create the database schema and populate it with realistic mock data.

SQL

```SQL
-- Create custom enum type for subscription status
CREATE TYPE sub_status AS ENUM ('active', 'canceled', 'expired');

-- 1. Users Table
CREATE TABLE users (
    user_id SERIAL PRIMARY KEY,
    email VARCHAR(255) UNIQUE NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    metadata JSONB -- To practice JSONB manipulation
);

-- 2. Subscription Plans
CREATE TABLE plans (
    plan_id SERIAL PRIMARY KEY,
    plan_name VARCHAR(100) UNIQUE NOT NULL,
    price_monthly DECIMAL(10, 2) NOT NULL
);

-- 3. User Subscriptions (Bridge Table)
CREATE TABLE subscriptions (
    subscription_id SERIAL PRIMARY KEY,
    user_id INT REFERENCES users(user_id) ON DELETE CASCADE,
    plan_id INT REFERENCES plans(plan_id),
    status sub_status NOT NULL,
    start_date DATE NOT NULL,
    end_date DATE
);

-- 4. Transactions Table (For heavy aggregation and analytics)
CREATE TABLE transactions (
    transaction_id SERIAL PRIMARY KEY,
    user_id INT REFERENCES users(user_id) ON DELETE CASCADE,
    amount DECIMAL(10, 2) NOT NULL,
    transaction_date TIMESTAMP WITH TIME ZONE NOT NULL
);

-- 5. Employees Table (Self-referencing for hierarchical/recursive queries)
CREATE TABLE employees (
    employee_id INT PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    manager_id INT REFERENCES employees(employee_id),
    department VARCHAR(50) NOT NULL,
    salary DECIMAL(10, 2) NOT NULL
);
```

## 3. The Mastery Practice Challenges

Work through these progressive challenges. Attempt to write the queries yourself first before looking at the solution hidden below each prompt.

### Challenge 1: The JSONB Deep-Dive

**Problem:** Extract the list of users who opted into marketing, use an `iPhone` to access the service, and live in the `US`.

SQL

```SQL
SELECT user_id, email, 
       metadata->>'device' AS device, 
       metadata->>'country' AS country
FROM users
WHERE (metadata->>'marketing_opt_in')::boolean = true
  AND metadata->>'device' = 'iPhone'
  AND metadata->>'country' = 'US';
```

_Why this matters:_ PostgreSQL handles semi-structured data effortlessly. Mastering the distinction between the `->` operator (returns JSONB) and the `->>` operator (returns text) is vital for indexing and querying configuration or event payloads.

### Challenge 2: Advanced Window Functions (Running Totals)

**Problem:** Calculate a running total of revenue generated over time, ordered by the transaction date. Output should show each transaction's ID, date, amount, and the cumulative revenue up to that point.

SQL

```SQL
SELECT transaction_id, 
       transaction_date, 
       amount,
       SUM(amount) OVER (ORDER BY transaction_date ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS running_total
FROM transactions;
```

_Why this matters:_ Window functions compute calculations across a set of table rows that are somehow related to the current row without collapsing them into a single output row. Using `ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW` ensures an exact running total.

### Challenge 3: Recursive CTEs (The Org Tree)

**Problem:** Write a recursive query to build a reporting hierarchy chain for every employee. Your output should show the employee's name, their department, and their full management path (e.g., `Sarah (CEO) -> Michael (VP Engineering) -> David (Eng Lead)`).

SQL

```SQL
WITH RECURSIVE org_path AS (
    -- Anchor member
    SELECT employee_id, name, manager_id, department,
           CAST(name AS TEXT) as path_string
    FROM employees
    WHERE manager_id IS NULL
    
    UNION ALL
    
    -- Recursive member
    SELECT e.employee_id, e.name, e.manager_id, e.department,
           CAST(op.path_string || ' -> ' || e.name AS TEXT)
    FROM employees e
    JOIN org_path op ON e.manager_id = op.employee_id
)
SELECT name, department, path_string 
FROM org_path;
```

_Why this matters:_ Self-referential hierarchies (like org charts, category trees, or thread replies) cannot be traversed efficiently using static joins. Recursive Common Table Expressions (CTEs) are the industry standard for walking these graphs.

### Challenge 4: Identifying Anomalies (Filtering with Window Functions)

**Problem:** Find any employee whose salary is more than **2 standard deviations** above their department's average salary. (This will catch the input typo on Dev Ryan's salary).

SQL

```SQL
WITH dept_stats AS (
    SELECT name, department, salary,
           AVG(salary) OVER(PARTITION BY department) as avg_dept_salary,
           STDDEV(salary) OVER(PARTITION BY department) as stddev_dept_salary
    FROM employees
)
SELECT name, department, salary, avg_dept_salary, stddev_dept_salary
FROM dept_stats
WHERE salary > (avg_dept_salary + (2 * COALESCE(stddev_dept_salary, 0)));
```

_Why this matters:_ Combining aggregations over a partition (`PARTITION BY`) with filtering logic in a CTE allows you to write clean, mathematical anomaly detection scripts directly inside your relational database.

### Challenge 5: Cohort Retention Analysis (The Mastery Boss Fight)

**Problem:** Calculate the Monthly Active Revenue churn. Identify users who had active paid subscriptions in `2025-03-01` but canceled or let them expire by `2025-06-01`, and calculate how much monthly revenue was lost from those specific users.

SQL

```SQL
WITH march_active AS (
    -- Users who had an active, paid plan during March 2025
    SELECT s.user_id, p.price_monthly, p.plan_name
    FROM subscriptions s
    JOIN plans p ON s.plan_id = p.plan_id
    WHERE s.start_date <= '2025-03-31'
      AND (s.end_date IS NULL OR s.end_date >= '2025-03-01')
      AND p.price_monthly > 0
),
june_status AS (
    -- The status of those same users by June 1st, 2025
    SELECT ma.user_id, ma.price_monthly,
           COALESCE(s.status, 'expired'::sub_status) as status_by_june
    FROM march_active ma
    LEFT JOIN subscriptions s ON ma.user_id = s.user_id 
      AND s.start_date <= '2025-06-01'
      AND (s.end_date IS NULL OR s.end_date >= '2025-06-01')
)
SELECT 
    SUM(price_monthly) FILTER (WHERE status_by_june != 'active') as total_monthly_revenue_churned,
    COUNT(user_id) FILTER (WHERE status_by_june != 'active') as total_users_churned
FROM june_status;
```

_Why this matters:_ Real analytics roles live and breathe cohort retention. This query forces you to conceptually merge cross-sectional dates with overlapping interval scopes.
