
In PostgreSQL, **constraints** are rules applied to columns or tables that prevent invalid data from entering your database. They are the ultimate line of defense for data integrity.

Here is the complete list of constraints you can use in PostgreSQL:

|**Constraint**|**Type**|**What it Does**|**Real-World Example**|
|---|---|---|---|
|**`NOT NULL`**|Column|Prevents a column from storing a `NULL` (empty) value.|Every user must have an `email` address.|
|**`UNIQUE`**|Column/Table|Ensures all values in a column (or a group of columns) are different.|No two users can register with the same `username`.|
|**`PRIMARY KEY`**|Column/Table|A combination of `NOT NULL` and `UNIQUE`. Uniquely identifies each row.|A `user_id` serial number.|
|**`FOREIGN KEY`** _(References)_|Column/Table|Links a column to a primary key in another table, ensuring the relationship exists.|An `order` cannot be placed by a `user_id` that does not exist.|
|**`CHECK`**|Column/Table|Enforces that values in a column must satisfy a specific boolean condition.|A `price` column must be greater than zero (`CHECK (price > 0)`).|
|**`DEFAULT`**|Column|_Technically a column modifier/attribute_, it automatically fills in a fallback value if no value is provided.|Setting `join_date` to `CURRENT_DATE` automatically upon sign-up.|
|**`EXCLUDE`**|Table|An advanced constraint that ensures if any two rows are compared on specified columns, at least one comparison returns false.|Preventing double-booking a conference room for overlapping times.|

### Pro-Tip: Column vs. Table Constraints

You can define most constraints in two ways:

- **Column Level:** Written directly next to the column name (best for single-column rules).
    
- **Table Level:** Written at the very bottom of the `CREATE TABLE` script (required if a rule spans **multiple columns**, like a composite unique key).
    



```SQL
CREATE TABLE inventory (
    item_id SERIAL PRIMARY KEY,                        -- Column Level Primary Key
    item_code VARCHAR(50) NOT NULL,                    -- Column Level Not Null
    price DECIMAL(10,2) CHECK (price > 0),             -- Column Level Check
    
    -- Table Level Composite Unique Constraint (item_code must be unique per department)
    CONSTRAINT unique_dept_item UNIQUE (item_code, department_id) 
);
```
