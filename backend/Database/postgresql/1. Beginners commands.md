
## The Concept: The Local Library Database

We will start with a simple design tracking **books** and **library members**. Instead of running a massive script to set everything up at once, **you will build, modify, and prune this database step-by-step** using the challenges below.

## Non-Select Practice Challenges

Follow these in exact sequence. Each step modifies the database schema or the data within it.

### Phase 1: Structuring & Reshaping (DDL)

These commands physically modify your database structure. _Warning: DDL operations can be destructive, so always double-check your syntax!_

#### Challenge 1: Creating Tables

- **Concept:** `CREATE TABLE`, primary keys, and data types.
    
- **Goal:** Create a table named `books_temp` with three columns:
    
    - `book_id` (integer, autoincrementing primary key)
        
    - `title` (text, cannot be null)
        
    - `author` (text)
        

SQL

```SQL
CREATE TABLE books_temp (
    book_id SERIAL PRIMARY KEY,
    title VARCHAR(255) NOT NULL,
    author VARCHAR(100)
);
```

#### Challenge 2: Renaming a Table

- **Concept:** `ALTER TABLE ... RENAME TO`.
    
- **Goal:** The table name `books_temp` was just a placeholder. Rename it to its permanent name: `books`.
    

SQL

```SQL
ALTER TABLE books_temp RENAME TO books;
```

#### Challenge 3: Adding a New Column

- **Concept:** `ALTER TABLE ... ADD COLUMN`.
    
- **Goal:** Add a new column to the `books` table named `published_year` to store four-digit integer years.
    

SQL

```SQL
ALTER TABLE books ADD COLUMN published_year INTEGER;
```

#### Challenge 4: Renaming a Column

- **Concept:** `ALTER TABLE ... RENAME COLUMN ... TO`.
    
- **Goal:** Rename the column `published_year` to simply `pub_year`.
    

SQL

```SQL
ALTER TABLE books RENAME COLUMN published_year TO pub_year;
```

#### Challenge 5: Modifying a Column's Data Type & Constraints

- **Concept:** `ALTER TABLE ... ALTER COLUMN ... TYPE`, adding constraints.
    
- **Goal:** Change the data type of the `author` column to `VARCHAR(150)` and enforce a constraint that it cannot be left empty (`NOT NULL`).
    

SQL

```SQL
-- Step 1: Change type and set NOT NULL
ALTER TABLE books ALTER COLUMN author TYPE VARCHAR(150);
ALTER TABLE books ALTER COLUMN author SET NOT NULL;
```

#### Challenge 6: Dropping a Column

- **Concept:** `ALTER TABLE ... DROP COLUMN`.
    
- **Goal:** The library decided they don't need to track the publication year anymore. Drop the `pub_year` column completely.
    

SQL

```SQL
ALTER TABLE books DROP COLUMN pub_year;
```

#### Challenge 7: Creating a Second Table (with Constraints)

- **Concept:** Default values and check constraints.
    
- **Goal:** Create a second table named `members` with:
    
    - `member_id` (autoincrementing primary key)
        
    - `name` (text, not null)
        
    - `join_date` (date, defaults to the current date if not specified)
        
    - `active_status` (boolean, defaults to `true`)
        

SQL

```SQL
CREATE TABLE members (
    member_id SERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    join_date DATE DEFAULT CURRENT_DATE,
    active_status BOOLEAN DEFAULT TRUE
);
```

### Phase 2: Manipulating Data (DML)

Now that your tables (`books` and `members`) are perfectly structured, let's practice adding, changing, and deleting the data inside them.

#### Challenge 8: Inserting a Single Row

- **Concept:** `INSERT INTO ... VALUES`.
    
- **Goal:** Insert a book into the `books` table: Title is `"The Hobbit"`, Author is `"J.R.R. Tolkien"`. Let PostgreSQL handle generating the ID.
    

SQL

```SQL
INSERT INTO books (title, author) 
VALUES ('The Hobbit', 'J.R.R. Tolkien');
```

#### Challenge 9: Inserting Multiple Rows in One Query

- **Concept:** Multi-row `INSERT`.
    
- **Goal:** Add three books to the `books` table in a single command:
    
    1. `"1984"` by `"George Orwell"`
        
    2. `"To Kill a Mockingbird"` by `"Harper Lee"`
        
    3. `"The Great Gatsby"` by `"F. Scott Fitzgerald"`
        

SQL

```SQL
INSERT INTO books (title, author) VALUES 
('1984', 'George Orwell'),
('To Kill a Mockingbird', 'Harper Lee'),
('The Great Gatsby', 'F. Scott Fitzgerald');
```

#### Challenge 10: Inserting with Default Values

- **Concept:** Overriding vs. respecting default values.
    
- **Goal:** Insert a new library member named `"Alice Smith"` into the `members` table. Do not specify a `join_date` or `active_status` in your query so PostgreSQL uses its defined default values.
    

SQL

```SQL
-- By leaving out join_date and active_status, PostgreSQL fills them in automatically.
INSERT INTO members (name) 
VALUES ('Alice Smith');
```

#### Challenge 11: Inserting with Explicit Default Declarations

- **Concept:** The `DEFAULT` keyword in insertions.
    
- **Goal:** Insert a member named `"Bob Jones"`, but explicitly write the keyword `DEFAULT` for the `join_date` and `active_status` columns.
    

SQL

```SQL
INSERT INTO members (name, join_date, active_status) 
VALUES ('Bob Jones', DEFAULT, DEFAULT);
```

#### Challenge 12: Updating a Single Value

- **Concept:** `UPDATE ... SET ... WHERE`.
    
- **Goal:** Change the author of the book `"1984"` to `"G. Orwell"`.
    

SQL

```SQL
UPDATE books 
SET author = 'G. Orwell' 
WHERE title = '1984';
```

> **Rule of Thumb:** _Never_ run an `UPDATE` without a `WHERE` clause unless you want to change every single row in your database to the same value!

#### Challenge 13: Updating Multiple Columns at Once

- **Concept:** Comma-separated `SET` updates.
    
- **Goal:** Bob Jones (from your `members` table) changed his name to `"Robert Jones"` and has chosen to deactivate his account. Update his name and set his `active_status` to `false` in a single query.
    

SQL

```SQL
UPDATE members 
SET name = 'Robert Jones', 
    active_status = FALSE 
WHERE name = 'Bob Jones';
```

#### Challenge 14: Deleting a Specific Row

- **Concept:** `DELETE FROM ... WHERE`.
    
- **Goal:** Remove `"The Great Gatsby"` from the `books` table.
    

SQL

```SQL
DELETE FROM books 
WHERE title = 'The Great Gatsby';
```

#### Challenge 15: Deleting Based on Multi-Condition Criteria

- **Concept:** Complex `DELETE`.
    
- **Goal:** Delete any member from the `members` table whose status is inactive (`false`) **and** joined before today's date.
    

SQL

```SQL
DELETE FROM members 
WHERE active_status = FALSE 
  AND join_date < CURRENT_DATE;
```

### Phase 3: Cleaning Up the House (Destructive DDL)

These commands are used when you want to wipe schemas, clear data instantly, or remove tables permanently.

#### Challenge 16: Emptying a Table Instantly (Truncating)

- **Concept:** `TRUNCATE` vs `DELETE`.
    
- **Goal:** Completely empty all data rows inside the `books` table without deleting the table structure itself.
    

SQL

```SQL
TRUNCATE TABLE books;
```

> **Key Takeaway:** `TRUNCATE` is much faster than `DELETE FROM table_name;` because it bypasses the transaction logging for individual rows and instantly drops and recreates the storage page.

#### Challenge 17: Dropping Tables Permanently

- **Concept:** `DROP TABLE`.
    
- **Goal:** Delete both the `books` and `members` tables completely from the database.
    

SQL

```SQL
DROP TABLE books;
DROP TABLE members;
```

#### Challenge 18: Safe Dropping (Preventing Errors)

- **Concept:** `DROP TABLE IF EXISTS`.
    
- **Goal:** Write a safe script that attempts to delete a table named `old_logs`, but does not crash or throw an error if the table does not exist.
    

SQL

```SQL
DROP TABLE IF EXISTS old_logs;
```
