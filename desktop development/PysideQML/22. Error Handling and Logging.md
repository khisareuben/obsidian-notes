## 📝 Step 1: Python Error Handling with Try/Except

python

```
# main.py
import sys, logging
from PySide6.QtCore import QObject, Slot, Signal
from PySide6.QtGui import QGuiApplication
from PySide6.QtQml import QQmlApplicationEngine

# Configure logging: saves logs to a file for offline debugging
logging.basicConfig(
    filename="app.log",
    level=logging.DEBUG,
    format="%(asctime)s - %(levelname)s - %(message)s"
)

class Backend(QObject):
    errorOccurred = Signal(str)

    @Slot()
    def risky_operation(self):
        try:
            # Example risky code: division by zero
            result = 10 / 0
            logging.info("Operation succeeded: %s", result)
        except Exception as e:
            # Log the error and notify QML
            logging.error("Error occurred: %s", e)
            self.errorOccurred.emit(str(e))

app = QGuiApplication(sys.argv)
engine = QQmlApplicationEngine()

backend = Backend()
engine.rootContext().setContextProperty("backend", backend)

engine.load("main.qml")
if not engine.rootObjects():
    sys.exit(-1)

sys.exit(app.exec())
```

## 🎨 Step 2: QML Error Dialog

// main.qml
import QtQuick

ApplicationWindow {
    visible: true

    Column {
        anchors.centerIn: parent

            text: "Run Risky Operation"

## 📝 Step 3: Logging Levels

You can use different levels depending on the situation:

- `logging.debug("Debug info")` → for development details
    
- `logging.info("General info")` → for normal operations
    
- `logging.warning("Something looks off")` → for potential issues
    
- `logging.error("Error occurred")` → for failures
    
- `logging.critical("System crash")` → for severe problems
    

## 🧠 Key Concepts Learned

- **Try/Except**: Catch errors gracefully instead of crashing.
    
- **Logging**: Save details to a file for offline debugging.
    
- **Signals**: Notify QML when errors occur.
    
- **Dialogs**: Show user‑friendly error messages.
    

## ⚡ Extra Ideas

- Add a **log viewer** in your app (read `app.log` into a QML `TextArea`).
    
- Use **custom error codes** for different modules.
    
- Combine with **Part 20 (Settings)** to let users choose log level (debug vs info).
