
**In PySide6 with QML,** _**States**_ **let you define alternate property configurations for UI elements, while** _**Transitions**_ **animate changes between those states. This is essential for building dynamic, interactive desktop apps.**

## 📝 Core Concepts of QML States

- **State**: A named configuration of property values for an item.
    
- **PropertyChanges**: Defines how properties change when a state is active.
    
- **when condition**: Activates a state based on a logical condition.
    
- **Default state**: The initial property values defined in QML before any state is applied.
    

## ⚙️ Example: Simple State in QML

qml

```JavaScript
Rectangle {
    width: 300; height: 200; color: "lightgray"

    Text {
        id: helloText
        text: "Hello World!"
        anchors.centerIn: parent
        font.pointSize: 24
        MouseArea { id: mouseArea; anchors.fill: parent }
    }

    states: State {
        name: "down"
        when: mouseArea.pressed
        PropertyChanges {
            target: helloText
            y: 160; rotation: 180; color: "red"
        }
    }

    transitions: Transition {
        from: ""; to: "down"; reversible: true
        ParallelAnimation {
            NumberAnimation { properties: "y,rotation"; duration: 500 }
            ColorAnimation { duration: 500 }
        }
    }
}
```

- **Default state**: Text is centered, black, upright.
    
- **Down state**: Text moves down, rotates, and turns red when clicked.
    
- **Transition**: Smooth animation between states.
    

## 🔄 State Machine in QML

For complex workflows, QML also supports **StateMachine**:

- Allows multiple states (e.g., `s1`, `s2`, `s3`) with **SignalTransition** triggered by events.
    
- Useful for modeling **application logic** beyond visual property changes.
    
- Runs asynchronously within the event loop.
    

## 📊 Comparison: States vs StateMachine

|**QML States**|**QML StateMachine**|
|---|---|
|Simple property changes|Complex event-driven logic|
|Best for UI animations|Best for workflows & app logic|
|Uses `State` + `Transition`|Uses `StateMachine` + `SignalTransition`|
|Lightweight|More structured, scalable|

## 🚀 Integration with PySide6

- Load QML files via `QQmlApplicationEngine` in Python.
    
- Use **QmlElement** decorator to expose Python classes to QML.
    
- Connect QML signals to Python slots for backend logic.

```JavaScript
// 1. Define breakpoints ONCE
    readonly property int mobileBreakpoint: 600
    readonly property int tabletBreakpoint: 840
    readonly property int desktopBreakpoint: 1240

    // 2. Derive states from width
    readonly property bool isMobile: width < mobileBreakpoint
    readonly property bool isTablet: width >= mobileBreakpoint && width < tabletBreakpoint  
    readonly property bool isDesktop: width >= tabletBreakpoint
```

```JavaScript
Rectangle {
    id: box
    color: "blue"  // default desktop
    width: 300
    visible: true

    states: State {
        name: "mobile"
        when: root.isMobile  // the switch
        PropertyChanges { target: box; color: "red"; width: 100; visible: false }
    }
}
```


# Full example

```JavaScript
import QtQuick
import QtQuick.Layouts

Item {
    id: root
    width: 800; height: 600

    // 1. Your breakpoint logic
    readonly property bool isMobile: width < 600

    // 2. ONE layout with everything
    RowLayout {
        id: mainLayout
        anchors.fill: parent
        spacing: 16

        Rectangle { // Sidebar
            id: sidebar
            color: "#333"
            Layout.preferredWidth: 240
            Layout.fillHeight: true
        }

        Rectangle { // Content
            id: content
            color: "#555"
            Layout.fillWidth: true
            Layout.fillHeight: true
        }
    }

    // 3. THE MAGIC: States
    states: State {
        name: "mobile"
        when: root.isMobile  // when this is true, apply changes below

        // What changes when we go mobile
        PropertyChanges { target: mainLayout; direction: ColumnLayout } // Row -> Column
        PropertyChanges { target: sidebar; Layout.preferredWidth: -1; Layout.preferredHeight: 60; Layout.fillWidth: true }
        PropertyChanges { target: content; Layout.fillWidth: true; Layout.fillHeight: true }
    }

    // 4. Optional: smooth animation
    transitions: Transition {
        NumberAnimation { properties: "preferredWidth,preferredHeight"; duration: 250 }
    }
}
```


### 3 rules to remember
- Set defaults for Desktop first - That's your "normal" code
- Only list what CHANGES in PropertyChanges - Don't repeat everything
- 1 when: controls the whole state - Not 10 if statements

```JavaScript
Item {
    id: root
    readonly property int bp: width

    Rectangle { id: box; width: 300 }

    states: [  // note the [ ] brackets = list
        State {
            name: "mobile"
            when: bp < 600
            PropertyChanges { target: box; width: 100 }
        },
        State {
            name: "tablet" 
            when: bp >= 600 && bp < 900
            PropertyChanges { target: box; width: 200 }
        },
        State {
            name: "desktop"
            when: bp >= 900
            PropertyChanges { target: box; width: 300 }
        }
    ]
}
```
