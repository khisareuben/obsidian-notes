
In PySide6 and QML, modal overlays and message prompts are split into two core concepts: **Popups** and **Dialogs**.

While they look similar, they have different structural roles under the `QtQuick.Controls` module. Here is a developer's cheat sheet for managing overlays in modern QML.

## 1. The Core Difference

At a high level, **`Dialog` actually inherits from `Popup`**.

- **`Popup`**: A completely blank, unstyled container. It has no default buttons, header, or footer. Use this for generic slide-out panels, custom tooltips, dropdown menus, or customized context bubbles.
    
- **`Dialog`**: A specialized popup specifically structured for communicating with the user. It is split into three zones: a **Header** (for titles), a **Content Area** (for custom inputs), and a **Footer** (pre-configured with standard platform buttons like OK and Cancel).
    

## 2. Using the Basic `Popup`

Because `Popup` doesn't enforce any layouts, you must define its size and how components align inside its `contentItem`.

### Basic Implementation

QML

```q
import QtQuick
import QtQuick.Controls

ApplicationWindow {
    id: app
    width: 400; height: 400
    visible: true

    Button {
        text: "Open Custom Popup"
        anchors.centerIn: parent
        onClicked: customPopup.open() // Opens the popup
    }

    Popup {
        id: customPopup
        
        // Position it in the center of the window (Overlay)
        parent: Overlay.overlay
        x: Math.round((parent.width - width) / 2)
        y: Math.round((parent.height - height) / 2)
        
        width: 250; height: 150
        modal: true                      // Dims the background and blocks clicks underneath
        focus: true                      // Grabs keyboard focus
        closePolicy: Popup.CloseOnEscape | Popup.CloseOnPressOutside // How to close it

        // Visual layout
        contentItem: Column {
            spacing: 15
            anchors.centerIn: parent

            Text { text: "This is a basic Popup"; font.pixelSize: 14 }
            Button {
                text: "Close"
                onClicked: customPopup.close()
            }
        }
    }
}
```

## 3. Using the `Dialog` Component

A `Dialog` makes prompting users easy because it handles standard platform button actions automatically. It fires built-in signals like `accepted()` or `rejected()` when those standard buttons are pressed.

### Built-in Dialog Implementation

QML

```q
import QtQuick
import QtQuick.Controls

ApplicationWindow {
    width: 400; height: 400
    visible: true

    Button {
        text: "Delete Item"
        anchors.centerIn: parent
        onClicked: warningDialog.open()
    }

    Dialog {
        id: warningDialog
        title: "Confirm Action" // Default Header title
        
        parent: Overlay.overlay
        anchors.centerIn: parent
        modal: true

        // 1. Footer Buttons
        standardButtons: Dialog.Ok | Dialog.Cancel // Auto-creates platform-styled buttons

        // 2. Main Content Area (automatically aligned)
        Text {
            text: "Are you sure you want to permanently delete this file?"
            wrapMode: Text.WordWrap
            width: 250
        }

        // 3. Handling User Actions
        onAccepted: {
            console.log("User clicked OK. Executing deletion...")
        }
        onRejected: {
            console.log("User clicked Cancel. Aborting...")
        }
    }
}
```

## 4. Crucial QML Overlay Best Practices 🧠

When handling popups or dialogs in PySide6 + QML, keep these three structural rules in mind:

### Rule 1: Always Use `parent: Overlay.overlay`

If you define a `Popup` nested inside a sub-component (like inside a nested button), QML will position the popup relative to that parent button. If the button is close to the screen edge, your popup will get cut off. Always set:

QML

```
parent: Overlay.overlay
anchors.centerIn: parent
```

This detaches the popup from its immediate local hierarchy and centers it over the entire `ApplicationWindow`.

### Rule 2: Note the Naming Collision (Qt Quick Controls vs Qt Quick Dialogs)

In Qt 6, there are two packages that export a "Dialog" type:

1. `import QtQuick.Controls` (Standard QML dialogs that you can style completely).
    
2. `import QtQuick.Dialogs` (Launches **native OS windows** like the Windows/macOS native file pickers or system alerts).
    

Make sure you import `QtQuick.Controls` if you want a custom-styled dialog inside your app canvas.
