

# 🎨 Additional Core Controls

### **PasswordField**

- **Purpose:** Secure text input where characters are hidden (e.g., login forms).
    
- **Behavior:** Uses `echoMode: TextInput.Password` to mask input.
    
- **Best Practices:**
    
    - Always combine with validation (minimum length, complexity).
        
    - Consider adding a “show/hide password” toggle for usability.
        
- **Example:**
    

qml

```python
TextField {
    placeholderText: "Enter password"
    echoMode: TextInput.Password
}
```

### **SpinBox**

- **Purpose:** Numeric input with increment/decrement arrows.
    
- **Behavior:** Provides bounded numeric values (`from`, `to`, `stepSize`).
    
- **Best Practices:**
    
    - Use for small ranges (e.g., quantity, rating).
        
    - For large ranges, prefer a `Slider`.
        
- **Example:**
    

qml

```python
SpinBox {
    from: 0
    to: 100
    stepSize: 5
    value: 10
}
```

### **Dial**

- **Purpose:** Circular numeric input, often used for volume or speed controls.
    
- **Behavior:** Rotational control with min/max values.
    
- **Best Practices:**
    
    - Use when a circular metaphor makes sense (volume knob).
        
    - Provide visual feedback (labels or icons).
        
- **Example:**
    

qml

```python
Dial {
    from: 0; to: 100
    value: 50
}
```

### **BusyIndicator**

- **Purpose:** Animated spinner to show loading states.
    
- **Behavior:** Runs continuously when `running: true`.
    
- **Best Practices:**
    
    - Use for background tasks (network requests, sync).
        
    - Pair with a message (“Loading data…”).
        
- **Example:**
    

qml

```python
BusyIndicator {
    running: true
    anchors.centerIn: parent
}
```

### **ToolTip**

- **Purpose:** Small pop‑up hints when hovering/tapping.
    
- **Behavior:** Appears automatically when hovering over a control.
    
- **Best Practices:**
    
    - Keep text short and informative.
        
    - Use for icons or buttons without labels.
        
- **Example:**
    

qml

```python
Button {
    text: "Save"
    ToolTip.text: "Click to save changes"
}
```

# 📂 More Containers & Navigation

### **StackView**

- **Purpose:** Navigation stack (push/pop pages).
    
- **Behavior:** Manages a stack of pages (like mobile navigation).
    
- **Best Practices:**
    
    - Use for wizard flows or multi‑step forms.
        
    - Avoid deep stacks; keep navigation simple.
        
- **Example:**
    

qml

```python
StackView {
    initialItem: Page { Label { text: "Home" } }
}
```

### **PageIndicator**

- **Purpose:** Dots showing current page in a SwipeView.
    
- **Behavior:** Syncs with `SwipeView.currentIndex`.
    
- **Best Practices:**
    
    - Always pair with `SwipeView`.
        
    - Keep dot count small (3–5 pages).
        
- **Example:**
    

qml

```python
SwipeView {
    id: swipe
    Item { Label { text: "Page 1" } }
    Item { Label { text: "Page 2" } }
}
PageIndicator {
    count: swipe.count
    currentIndex: swipe.currentIndex
}
```

### **Drawer**

- **Purpose:** Slide‑out side menu (mobile‑style).
    
- **Behavior:** Hidden by default, slides in when opened.
    
- **Best Practices:**
    
    - Use for navigation menus.
        
    - Keep content lightweight (links, icons).
        
- **Example:**
    

qml

```python
Drawer {
    width: 200
    Label { text: "Menu Item" }
}
```

### **ScrollView**

- **Purpose:** Adds scrolling to content.
    
- **Behavior:** Wraps content in a scrollable area.
    
- **Best Practices:**
    
    - Use for long text or lists.
        
    - Avoid nesting multiple scroll views.
        
- **Example:**
    

qml

```python
ScrollView {
    TextArea { text: "Long text goes here..." }
}
```

### **Pane**

- **Purpose:** Lightweight container for grouping controls.
    
- **Behavior:** Provides padding and background styling.
    
- **Best Practices:**
    
    - Use to visually separate sections.
        
    - Combine with `GroupBox` for labeled groups.
        
- **Example:**
    

qml

```python
Pane {
    Label { text: "Grouped content" }
}
```

# 📊 Extra Advanced Components

### **Repeater**

- **Purpose:** Dynamically generate repeating UI elements.
    
- **Behavior:** Creates items for each element in a model.
    
- **Best Practices:**
    
    - Use for small lists; for large datasets, prefer `ListView`.
        
- **Example:**
    

qml

```python
Repeater {
    model: 5
    Rectangle { width: 50; height: 50; color: "lightblue" }
}
```

### **Loader**

- **Purpose:** Lazy load components only when needed.
    
- **Behavior:** Loads QML files dynamically.
    
- **Best Practices:**
    
    - Use for dialogs, popups, or heavy components.
        
- **Example:**
    

qml

```python
Loader {
    active: true
    source: "Dialog.qml"
}
```

### **TreeView**

- **Purpose:** Hierarchical data display (like file explorers).
    
- **Behavior:** Requires a hierarchical model (`QAbstractItemModel`).
    
- **Best Practices:**
    
    - Use for structured data (folders, categories).
        
- **Example:** Typically bound to a Python model.
    

### **TableView with Models**

- **Purpose:** Efficient tabular data binding.
    
- **Behavior:** Works with `QAbstractTableModel`.
    
- **Best Practices:**
    
    - Use for large datasets (billing, records).
        
    - Implement sorting/filtering in the model.
        

### **Calendar**

- **Purpose:** Full calendar view for date selection.
    
- **Behavior:** Displays month view with selectable dates.
    
- **Best Practices:**
    
    - Use for scheduling apps.
        
    - Pair with `DatePicker` for compact input.
        
- **Example:**
    

qml

```python
Calendar {
    selectedDate: Qt.date(2026, 4, 13)
}
```

### **DatePicker / TimePicker**

- **Purpose:** Specialized date/time input.
    
- **Behavior:** Provides dropdowns for date/time selection.
    
- **Best Practices:**
    
    - Use for forms requiring precise scheduling.
        
- **Example:**
    

qml

```python
DatePicker { }
TimePicker { }
```

# 🎬 Visual & Animation Components

### **AnimatedImage**

- **Purpose:** Play GIFs or sprite animations.
    
- **Behavior:** Loops automatically.
    
- **Best Practices:**
    
    - Use for loading animations or fun effects.
        
- **Example:**
    

qml

```python
AnimatedImage {
    source: "loading.gif"
}
```

### **Transitions & States**

- **Purpose:** Smooth UI changes between modes.
    
- **Behavior:** Define states and animations.
    
- **Best Practices:**
    
    - Use for expanding/collapsing panels.
        
    - Keep animations short (<500ms).
        
- **Example:**
    

qml

```python
Rectangle {
    width: 100; height: 100; color: "red"
    states: State {
        name: "expanded"
        PropertyChanges { target: parent; width: 200; height: 200 }
    }
    transitions: Transition {
        NumberAnimation { properties: "width,height"; duration: 500 }
    }
}
```

### **ShaderEffect**

- **Purpose:** Custom GPU effects for visuals.
    
- **Behavior:** Runs GLSL shaders inside QML.
    
- **Best Practices:**
    
    - Use for blur, glow, or custom filters.
        
    - Avoid heavy shaders on low‑end hardware.
        

### **Canvas**

- **Purpose:** Custom drawing with JavaScript.
    
- **Behavior:** Provides a 2D drawing context.
    
- **Best Practices:**
    
    - Use for charts, custom graphics, or signatures.
        
- **Example:**
    

qml

```python
Canvas {
    onPaint: {
        var ctx = getContext("2d")
        ctx.fillStyle = "blue"
        ctx.fillRect(10, 10, 80, 80)
    }
}
```

## 🧠 Key Takeaways

- These components extend QML beyond basics — covering **secure inputs, navigation, dynamic data, and custom visuals**.
    
- Use **Repeater/Loader** for efficiency, **TreeView/TableView** for structured data, and **Transitions/ShaderEffect** for polish.
    
- Always balance **usability vs performance** — animations and heavy visuals should be optimized for rural/low‑end hardware contexts.
