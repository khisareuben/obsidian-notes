
### Pattern 1: The Sibling Way (Written alongside the element)

In this pattern, the shadow and the target element are siblings (both children of the same parent).

QML

```python
Item {
    id: container

    // 1. Shadow is written first
    RectangularShadow {
        id: shadow
        anchors.fill: card // Anchor to the card
        // ... shadow properties
    }

    // 2. The target card is written second (so it draws on top)
    Rectangle {
        id: card
        width: 100; height: 100
    }
}
```

#### Why we do it:

- **Natural Z-ordering**: QML draws items from top to bottom. Since the shadow is declared _before_ the card, the engine draws the shadow first, then draws the card on top of it.
    
- **Easy positioning**: You can simply use `anchors.fill: card` to make the shadow mimic the size and position of the card dynamically.
    

### Pattern 2: The Nested Way (Written inside the element)

In this pattern, the shadow is declared as a child _inside_ the element itself.

QML

```python
Rectangle {
    id: card
    width: 100; height: 100
    color: "white"

    // Shadow is nested INSIDE the card
    RectangularShadow {
        anchors.fill: parent
        // ...
    }
}
```

#### The Problem with standard nesting:

If you do this naively, QML will render the shadow _on top_ of the card, blocking the card's color or child elements. This is because children are always drawn on top of their parents by default.

#### Why developers do it anyway (and how they fix it):

Despite the rendering order, developers nest shadows inside components to make them **self-contained**. If you write a custom button, you want the shadow inside `Button.qml` so you don't have to write a sibling shadow every single time you use that button.

To make nested shadows work correctly, developers use one of two techniques:

1. **Negative Z-ordering**: Force the nested shadow to render _behind_ its parent:
    
    QML
    
    ```python
    Rectangle {
        id: card
        // ...
        RectangularShadow {
            anchors.fill: parent
            z: -1 // 👈 Forces the shadow to paint underneath the parent card
        }
    }
    ```
    
2. **The Layer Trick**: In Qt 6, you can tell a component to render itself and its shadow as a single visual layer using `layer.enabled`:
    
    QML
    
    ```python
    Rectangle {
        id: card
        layer.enabled: true
        layer.effect: MultiEffect {
            shadowEnabled: true // Shadow is processed directly on the card's layer
        }
    }
    ```
    

### Summary: Which one should you use?

- Use the **Sibling Way** when you are building quick layouts in a single file where you can easily keep track of which items are layered over others.
    
- Use the **Nested Way (with `z: -1`)** when you are building reusable, self-contained components (like custom buttons or cards) that need to carry their own shadow rules wherever they go.


```python

import QtQuick
import QtQuick.Controls
import QtQuick.Effects

ApplicationWindow {
    visible: true
    width: 640
    height: 480
    title: qsTr("Application Window")

    Rectangle {
        id: windowBackground
        width: 400; height: 400
        color: "#1e1e1e"

        # 1. The Shadow Element (placed behind the card)
        RectangularShadow {
            anchors.fill: card
            
            # Match the rounded corners of your target element
            radius: card.radius 
            
            # Shadow configuration (mimicking CSS box-shadow)
            blur: 15.0
            spread: 2.0
            color: "#80000000" // 50% opacity black shadow
            
            # Offset coordinates to shift the shadow down and right
            offset: Qt.vector2d(0, 6) 
        }

        # 2. The Card itself (placed on top of the shadow)
        Rectangle {
            id: card
            width: 240; height: 140
            radius: 12
            color: "#2b2b2b"
            anchors.centerIn: parent

            Label {
                text: "Fast SDF Shadow"
                color: "white"
                anchors.centerIn: parent
            }
        }
    }

}
```
