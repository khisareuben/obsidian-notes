
**Part 23: Modular Architecture in PySide6 + QML**. This part is about structuring your apps so they’re clean, scalable, and easy to maintain. Instead of dumping all logic into one file, you’ll learn how to split your project into **modules** using the **MVVM (Model–View–ViewModel)** pattern — a common approach in Qt/QML apps.

# Part 24: Modular Architecture

## 📂 Project Structure

Here’s how you can organize your files:

Code

```
pyside6_qml_modular/
├── main.py              # Entry point
├── backend/
│   ├── __init__.py
│   ├── data_model.py    # Handles data (Model)
│   ├── logic.py         # Business logic (ViewModel)
└── ui/
    └── main.qml         # User interface (View)
```

## 📝 Step 1: Data Model (Model Layer)

This layer manages raw data (e.g., records, API responses, database rows).



```python
# backend/data_model.py
class Institution:
    def __init__(self, name, subscription_status, balance):
        self.name = name
        self.subscription_status = subscription_status
        self.balance = balance
```

## 📝 Step 2: Business Logic (ViewModel Layer)

This layer connects data to the UI, exposing signals and slots.



```python
# backend/logic.py
import sys
from PySide6.QtCore import QObject, Signal, Slot
from .data_model import Institution

class InstitutionManager(QObject):
    institutionAdded = Signal(str)

    def __init__(self):
        super().__init__()
        self.institutions = []

    @Slot(str, str, float)
    def add_institution(self, name, status, balance):
        inst = Institution(name, status, balance)
        self.institutions.append(inst)
        self.institutionAdded.emit(f"Institution {name} added successfully")
```

## 📝 Step 3: Entry Point (main.py)

This wires everything together.



```python
# main.py
import sys
from PySide6.QtGui import QGuiApplication
from PySide6.QtQml import QQmlApplicationEngine
from backend.logic import InstitutionManager

app = QGuiApplication(sys.argv)
engine = QQmlApplicationEngine()

manager = InstitutionManager()
engine.rootContext().setContextProperty("institutionManager", manager)

engine.load("ui/main.qml")
if not engine.rootObjects():
    sys.exit(-1)

sys.exit(app.exec())
```

## 🎨 Step 4: QML UI (View Layer)

The UI interacts only with the exposed `InstitutionManager`.


```q
// ui/main.qml
import QtQuick
import QtQuick.Controls

ApplicationWindow {
    visible: true
    width: 500
    height: 300
    title: "Modular Architecture Example"

    Column {
        anchors.centerIn: parent
        spacing: 10

        TextField { id: nameField; placeholderText: "Institution Name" }
        TextField { id: statusField; placeholderText: "Subscription Status" }
        TextField { id: balanceField; placeholderText: "Balance" }

        Button {
            text: "Add Institution"
            onClicked: institutionManager.add_institution(
                nameField.text, statusField.text, parseFloat(balanceField.text)
            )
        }

        Label { id: resultLabel; text: "" }
    }

    Connections {
        target: institutionManager
        onInstitutionAdded: resultLabel.text = message
    }
}
```

## 🧠 Key Concepts Learned

- **Model** → Raw data structures (e.g., Institution class).
    
- **ViewModel** → Business logic, signals, slots, data management.
    
- **View** → QML UI, interacts only with exposed properties/slots.
    
- **Separation of concerns** → Easier to debug, extend, and maintain.
    

## ⚡ Extra Ideas

- Add a **database layer** (SQLite) inside `data_model.py`.
    
- Add **networking logic** (Part 21) inside `logic.py`.
    
- Keep UI files separate in `ui/` for clarity.
    
- Use **MVVM** consistently: QML never manipulates raw data directly.
