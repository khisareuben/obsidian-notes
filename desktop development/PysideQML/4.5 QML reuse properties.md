
# QML Properties & Reuse

## 🔹 Why use properties?

- **Consistency**: Define a value once, reuse everywhere.
    
- **Maintainability**: Change in one place updates all references.
    
- **Flexibility**: Properties can be bound to expressions, making UI adaptive.
    

## 🔹 Defining local properties

You can declare custom properties inside any QML item:

qml

```JavaScript
Rectangle {
    width: 400
    height: 300

    // Local reusable properties
    property color primaryColor: "steelblue"
    property int screenWidth: 400

    Rectangle {
        width: parent.screenWidth / 2
        height: 100
        color: parent.primaryColor
    }
}
```

- `property <type> <name>: <value>`
    
- Types: `int`, `real`, `string`, `color`, `bool`, `url`, `var`, etc.
    
- Access via `parent.propertyName` or `id.propertyName`.
    

## 🔹 Global properties with Singletons

For app-wide consistency, use a **singleton**:

**Theme.qml**

qml

```JavaScript
pragma Singleton
import QtQuick 2.15

QtObject {
    property color primaryColor: "#3498db"
    property int defaultWidth: 800
    property int defaultHeight: 600
}
```

Usage:

qml

```JavaScript
Rectangle {
    width: Theme.defaultWidth
    height: Theme.defaultHeight
    color: Theme.primaryColor
}
```

- Singleton ensures one shared instance across all QML files.
    
- Perfect for **themes**, **screen sizes**, and **design systems**.
    

## 🔹 Property alias

Expose a child property through the parent:

qml

```JavaScript
Rectangle {
    id: root
    property alias mainColor: child.color

    Rectangle {
        id: child
        color: "tomato"
    }
}
```

- `alias` creates a shortcut.
    
- Useful for **component APIs** (making reusable QML components configurable).
    

## 🔹 Best practices

- **Centralize constants**: Use a singleton for colors, fonts, spacing.
    
- **Avoid magic numbers**: Replace with named properties.
    
- **Responsive design**: Bind properties to `Screen.width` / `Screen.height`.
    
- **Document properties**: Add comments for clarity.
    

## 🔹 Example: Responsive theme

qml

```JavaScript
pragma Singleton
import QtQuick 2.15

QtObject {
    property color backgroundColor: "#f5f5f5"
    property color accentColor: "#e74c3c"

    property int smallScreen: 480
    property int mediumScreen: 768
    property int largeScreen: 1024
}
```

Usage:

qml

```JavaScript
Rectangle {
    width: Screen.width < Theme.mediumScreen ? Theme.smallScreen : Theme.largeScreen
    color: Theme.backgroundColor
}
```



## 🔹 Correct way to declare a singleton

1. **Theme.qml**
    

qml

```JavaScript
pragma Singleton
import QtQuick 2.15

QtObject {
    property color textColor: "#3498db"
}
```

2. **qmldir file** (in the same folder as `Theme.qml`)
    

Code

```
singleton Theme 1.0 Theme.qml
```

This tells QML that `Theme.qml` is a singleton named `Theme`.

3. **Import in your main QML file**
    

```JavaScript
import QtQuick
import QtQuick.Controls
import Theme 1.0   // ✅ instead of "theme.qml"
```

4. **Usage**
    

```JavaScript
ApplicationWindow {
    visible: true
    width: 640
    height: 480
    title: qsTr("Application window")

    Text {
        anchors.centerIn: parent
        text: "What is going on today"
        font.pixelSize: 20
        color: Theme.textColor   // ✅ works now
    }
}
```
    

## 🔹 Quick alternatives (if you don’t want a singleton yet)

- **Local property**:
    
    qml
    
    ```JavaScript
    ApplicationWindow {
        property color textColor: "#3498db"
    
        Text {
            color: textColor
        }
    }
    ```
    
- **Context property from Python/C++**: expose `textColor` via backend.
